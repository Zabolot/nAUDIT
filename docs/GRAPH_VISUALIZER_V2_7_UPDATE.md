## Обновление: Graph Visualizer v2.7

Дата: 2025-11-16

Краткое описание
- В этом документе описаны изменения, улучшения и отладочные рекомендации по компоненту визуализации графов (Plotly + PyVis) версии 2.7 в проекте nAUDIT.

Основные цели изменений
- Надёжное отключение физики в PyVis (vis.js) и фиксирование позиций узлов.
- Группировка и покраска узлов по папкам (folder-priority coloring).
- Чёткое отображение количества ошибок на узлах (числа вместо пустых маркеров; ✓ для «OK»).
- Оптимизация рендера рёбер в Plotly (один trace для edges) и лимиты для больших графов.
- Экспорт HTML (Plotly + PyVis) в папку отчётов, а также дампы для отладки.
- Использование GPU (если доступно) для ускорения расчёта layout.
- Синхронизация Tree ↔ Graph: дерево является источником правды для соответствия файл→ошибки.

Ключевые изменения кода
- Файл: `n_audit/gui/graph_visualizer_v2_7.py`
  - Новые/изменённые методы:
    - populate_from_report(report, project_root, files_with_issues=None)
      - Принимает внешний маппинг `files_with_issues` (формируется в ErrorTreeWidget) — теперь дерево является источником правды.
    - _normalize_path(file_path, project_root)
      - Унификация путей для корректного сопоставления между отчётом и файлами в проекте.
    - _calculate_positions_gpu_accelerated(...)
      - Альтернативный путь с использованием torch/CUDA. Имеет fallback на CPU.
    - _generate_plotly_html(...) и _generate_pyvis_html(...)
      - Plotly: edges объединены в один Scatter для производительности.
      - PyVis: серверные опции + инжектируемый JS для надёжного отключения physics.
    - focus_on_node(file_path)
      - Plotly: добавляется селекционный trace `__naudit_selection` и делается анимированная релокация (relayout) на выбранный узел.
      - PyVis: selectNodes + moveTo/focus по координатам.
    - export_current_graph()
      - Экспортирует оба HTML в %USERPROFILE%\\.naudit\\reports\\graphs\\

Файлы, которые используют изменения
- `n_audit/gui/tree_widget.py` — теперь формирует `files_with_issues` и передаёт в graph.
- `n_audit/gui/error_visualization.py` — популяция дерева выполняется первой; граф получает mapping из дерева.

Как пользоваться (краткий гайд)
1. Открыть вкладку "Graph" или режим "Both" (split view). Дерево слева — источник соответствия ошибок.
2. Выбрать файл в дереве — граф центрируется на соответствующем узле и подсвечивает его.
3. Для экспорта текущего вида графа используйте метод/кнопку, которая вызывает `export_current_graph()` — сгенерируются:
   - Plotly HTML: %USERPROFILE%\\.naudit\\reports\\graphs\\graph_plotly_*.html
   - PyVis HTML: %USERPROFILE%\\.naudit\\reports\\graphs\\graph_pyvis_*.html
   - Отладочный JSON: %USERPROFILE%\\.naudit\\reports\\debug_graph_files_info.json

Отладка поведения в .exe (частые причины различий)
- Частая причина: другое окружение (версия vis.js или timing инициализации в QWebEngine) при упаковке в .exe.
- Шаги для диагностики:
  1. Нажмите экспорт в GUI — получите HTML и debug JSON.
 2. Откройте экспортированный PyVis HTML в браузере (Chrome/Edge). Откройте DevTools (F12) и проверьте консоль на сообщения, которые инжектируются скриптом (по префиксу [nAUDIT] или [PyVis]).
 3. В консоли выполните поиск по `physics` и `fixed` у узлов (см. window.network.getOptions() и window.network.body.data.nodes.get()).
 4. Если physics оказывается включённым после инициализации — обратите внимание на ошибки загрузки внешних скриптов (CSP) или на то, что vis.js грузится другой версии.
 5. В debug JSON смотрите `files_info` — это окончательная карта node→errors, которая используется при генерации HTML. Если там сопоставления неправильны, сначала проверьте дерево: оно должно содержать ожидаемые пути и ключи.

Рекомендации по тестированию в .exe
- Экспортируйте HTML и откройте локально в браузере; если поведение отличается — проблема в окружении/пакете, а не в логике Python.
- Проверьте, что в экспортированном HTML присутствует наш инжектируемый JS-блок (поиск текста `__naudit_selection` или `naudit_disable_physics`).

Ограничения и дальнейшие шаги
- Текущая реализация полагается на то, что ErrorTreeWidget покрывает большинство соответствий файл→issue. Для особо странных форматов отчётов можно добавить более агрессивные эвристики (basename/suffix/fuzzy). Это отмечено как опциональная задача.
- В .exe возможны расхождения связаны с упаковкой статических ресурсов (версии vis.js/plotly). В таком случае рекомендовано фиксировать версии библиотек в билде и/или встраивать необходимые JS в ресурс exe.

Контакт для обратной связи
- Если после проверки экспорта остаются несоответствия, приложите:
  - экспортированный PyVis HTML
  - %USERPROFILE%\\.naudit\\reports\\debug_graph_files_info.json
  - краткое описание, какие узлы/файлы отображаются неверно
