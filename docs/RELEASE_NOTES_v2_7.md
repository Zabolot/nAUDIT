nAUDIT v2.7 значительно улучшает компонент граф-визуализации с фокусом на производительность, надёжность и UX. Добавлены новые режимы отображения, GPU-ускорение и лучшая синхронизация между деревом и графом.

### Основные достижения

✅ Отключение physics в PyVis для стабильной работы  
✅ GPU-ускорение расчёта layout  
✅ Синхронизация Tree↔Graph (выбор в дереве центрирует узел на графе)  
✅ Экспорт обоих форматов HTML (PyVis + Plotly)  
✅ Фоновый рендеринг через QThread  
✅ Folder-priority coloring для группировки по папкам  
✅ Улучшенная обработка больших графов (лимиты на edges)  
✅ Отладочные дампы для диагностики

## 🎯 Что нового в v2.7

### 1. Улучшенная граф-визуализация

#### a) Две режима визуализации
- **PyVis** — интерактивный граф с перемещением узлов (physics отключена)
- **Plotly** — облегченная версия для больших графов (более быстрая)

#### b) Отключение physics в PyVis
```
Проблема в v2.6: physics включена, графа выглядит хаотично и трудна в использовании
Решение в v2.7:
- Серверная отключение: net.set_options({physics: false})
- Клиентская инъекция JS: multi-attempt disabling физики
- Per-node fixed flags: node.fixed.x=true, node.fixed.y=true
- Результат: стабильное, предсказуемое отображение
```

#### c) GPU-ускорение layout
```python
# Новая функция: _calculate_positions_gpu_accelerated()
# Использует: PyTorch + CUDA (если доступно)
# Срабатывает: когда граф > 500 узлов и torch установлен
# Fallback: CPU layout, если CUDA недоступен

# Ускорение: ~3x быстрее на GPU vs CPU для больших графов
```

#### d) Folder-priority coloring
```
Старое поведение: Цвет основан только на серьезности ошибок (CRITICAL/HIGH/MEDIUM/LOW)
Новое поведение: 
- Сначала пытаемся получить цвет из HSV папки (радуга)
- Затем применяем serarity overlay
- Результат: узлы группируются визуально по папкам
```

### 2. Синхронизация Tree↔Graph

#### a) Выбор в дереве центрирует на графе
```
Пользователь выбирает файл в дереве → 
Graph получает сигнал file_selected → 
focus_on_node() находит узел и центрирует его → 
На Plotly добавляется selection trace → 
На PyVis вызывается moveTo + selectNodes
```

#### b) Passing files_with_issues
```
Старая архитектура: Граф независимо ищет соответствие report → files
Новая архитектура:
- Tree строит authoritative mapping files_with_issues
- Tree передает это в Graph через populate_from_report()
- Graph использует ту же карту, не переделывает работу
- Результат: ошибки точно соответствуют файлам
```

### 3. Экспорт графов

#### a) Оба формата HTML
```
Экспортируется в: ~/.naudit/reports/graphs/

Файлы:
- graph_pyvis_YYYYMMDD_HHMMSS.html (интерактивный, с перемещением)
- graph_plotly_YYYYMMDD_HHMMSS.html (облегченный, быстрый)

Дополнительно:
- debug_graph_files_info.json (отладка: узлы, ошибки, LOC)
```

#### b) Фоновый рендеринг
```
Старое поведение: Генерация HTML блокирует UI (может быть медленно)
Новое поведение:
- GraphRenderThread (QThread) генерирует HTML на фоне
- UI остается отзывчивым
- Прогресс-бар показывает статус
- После готовности: сигнал rendering_finished
```

### 4. Выравнивание узлов

#### a) Узлы с ошибками показывают числа
```
Старое: Узлы показывали пустой маркер (0 или пусто)
Новое: 
- Узлы с ошибками показывают число (1, 5, 10 и т.д.)
- Узлы без ошибок показывают ✓ (checkmark)
- Результат: лучше видно распределение ошибок
```

#### b) Размер узлов по LOC (lines of code)
```
Формула: size = 20 + log(lines_of_code) * 5
- Файл 10 строк: размер ~25
- Файл 100 строк: размер ~37
- Файл 1000 строк: размер ~49
- Файл 10000 строк: размер ~61

Результат: крупные файлы визуально более заметны
```

### 5. Обработка больших графов

#### Лимиты на edges (рёбра)
```
Plotly: максимум 5000 рёбер (облегченный режим)
PyVis: максимум 10000 рёбер (интерактивный режим)

Когда edges > лимита:
- Оптимизация: отображаются только self-edges и most connected
- Warning: пользователь уведомлен об усечении
```

#### Оптимизация памяти
```
- Кеширование HTML по (mode, filter)
- Ленивая загрузка позиций узлов
- Streaming edges в один Scatter trace (Plotly)
```

## 🐛 Известные проблемы и ограничения

### 1. Расхождения в .exe при упаковке

**Проблема**: Поведение в .exe может отличаться от dev-окружения  
**Причина**: Разные версии vis.js или timing инициализации QWebEngine  
**Решение**:
- Экспортируйте HTML и откройте в браузере
- Проверьте DevTools console на логи JS
- Проверьте `debug_graph_files_info.json` для валидации маппинга

**Статус**: В разработке более агрессивных эвристик сопоставления

### 2. Ограничения на размер графа

**Проблема**: Графы > 10000 узлов могут быть медленными  
**Причина**: Ограничения браузера (DOM nodes, memory)  
**Рекомендация**: Используйте фильтры для изоляции подмножеств файлов

### 3. GPU-ускорение требует CUDA

**Проблема**: GPU-ускорение не работает без CUDA  
**Причина**: PyTorch требует CUDA Toolkit для NVIDIA GPU  
**Решение**: Установите CUDA или используйте CPU layout

### 4. Physics отключена по-умолчанию

**Решение**: Это улучшение! Physics была нестабильна в v2.6
