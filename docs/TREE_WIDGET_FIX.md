# Исправление: Дерево ошибок не отображается правильно (v4.0.1)

## Проблема

После исправления AttributeError ошибок в v4.0, обнаружена проблема с отображением интерактивного дерева ошибок в вкладке "🌳 Ошибки" главного окна приложения.

### Симптомы
- Дерево ошибок не отображается в GUI
- При запуске аудита вкладка остаётся пустой
- Функциональность, по видимому, работает, но пользователь не видит ошибки

## Корневая причина

**Неправильная категоризация ошибок в методе `ErrorTreeWidget._get_category()`**

Файл: `n_audit/gui/tree_widget.py`, метод `_get_category()` (строка ~242)

### Проблемный код (ДО):
```python
def _get_category(self, issue_type: str, code: str) -> IssueCategory:
    """Определить категорию по типу"""
    if issue_type == 'security':
        return IssueCategory.SECURITY
    
    if code and code[0] == 'E':
        return IssueCategory.ERROR      # ⚠️ ПРОБЛЕМА: Все E501 попадают сюда!
    
    if code and code[0] in ['W', 'C']:
        return IssueCategory.WARNING
    
    return IssueCategory.STYLE
```

### Почему это проблема

Метод **полностью игнорирует параметр `issue_type`** и вместо этого полагается ТОЛЬКО на первый символ кода ошибки. Это приводит к неправильной категоризации:

- **Ошибки вида `style_issue` (E501 "line too long")** должны быть в категории `STYLE`, но попадали в `ERROR` только потому что код начинается с 'E'
- Все 2557 ошибок в проекте имели `issue_type='style_issue'`, поэтому они ВСЕ неправильно категоризировались
- В результате в дереве отображалась только одна категория, что выглядело как не работающее дерево

### Отладка

Используя `test_tree_debug.py`, обнаружено:
```
Tree items after populate: 1
    Category 0: 🔴 Ошибки (2557)  ← ВСЕ в одной категории!
```

Должно быть:
```
Tree items after populate: 1
    Category 0: 🟡 Стиль/Оформление (2557)  ← Правильная категория
```

## Решение

**Исправить метод `_get_category()` для правильного использования `issue_type`**

### Исправленный код (ПОСЛЕ):
```python
def _get_category(self, issue_type: str, code: str) -> IssueCategory:
    """Определить категорию по типу"""
    # Сначала проверяем явный тип из issue_type
    if issue_type == 'security':
        return IssueCategory.SECURITY
    elif issue_type == 'style_issue':
        return IssueCategory.STYLE
    elif issue_type == 'warning':
        return IssueCategory.WARNING
    elif issue_type == 'error':
        return IssueCategory.ERROR
    
    # Если issue_type не определен, используем код для определения
    if code and code[0] == 'E':
        return IssueCategory.ERROR
    
    if code and code[0] in ['W', 'C']:
        return IssueCategory.WARNING
    
    return IssueCategory.STYLE
```

### Ключевые улучшения:
1. ✅ **Явная проверка `issue_type` в начале** - использует правильный тип, который уже установлен в `CodeIssue`
2. ✅ **Обработка всех возможных типов**: `'security'`, `'style_issue'`, `'warning'`, `'error'`
3. ✅ **Резервная логика на коде** - если `issue_type` не определен, используем первый символ кода (для совместимости)
